# Realistic Travel Planner · 务实旅行规划

**让路线、住宿、天气和预算，组成一趟经得起推敲的旅行。**

[![Validate](https://github.com/yilianghe/realistic-travel-planner-skill/actions/workflows/validate.yml/badge.svg)](https://github.com/yilianghe/realistic-travel-planner-skill/actions/workflows/validate.yml)
[![Python](https://img.shields.io/badge/Python-3.10%2B-blue)](realistic-travel-planner/scripts/audit_plan.py)
[![License: MIT](https://img.shields.io/badge/License-MIT-green.svg)](LICENSE)

Realistic Travel Planner 是一套面向支持 `SKILL.md` 的 AI agent 的旅行规划工作流。
它把旅行者的作息、体力、体验偏好与实际的时间、费用约束放在一起，要求 agent
交付有依据的路线、住宿判断、天气安排和调整方案，并对复杂时间表与预算运行检查。

**每一个推荐都应回答：为什么适合你、实际要付出什么、条件变化后怎么改。**

## 它有什么不同

### 让偏好真正改变行程

确认你想获得的体验、愿意早起到几点、能走多久、同行者需要怎样的照顾，以及
更愿意把钱花在住宿、交通还是体验上。这些信息直接影响目的地取舍和活动密度。
已经回答的条件会沿用，只补问真正影响决定的信息；条件足够后就进入路线规划。

### 把门到门的时间算完整

路线落实到**起点、停车或入口、点位顺序、分段交通、返回方式**；徒步还会区分
驾车接近、实际步行、爬升、摄影停留、恢复和折返条件。

出门整理、候车、转乘、停车、寄存、安检、排队、吃饭和休息，都进入同一条时间线。
例如，到博物馆大门和完成安检入馆，会作为两个不同的时间节点处理。

### 给行程设计删减顺序

| 类型 | 回答的问题 |
|---|---|
| **核心项目** | 这一天最值得保护的体验是什么？ |
| **可删项目** | 多花多少时间与费用，什么情况下删掉？ |
| **建议跳过** | 哪些热门地点与这次的兴趣、路线、季节或体力不匹配？ |

遇到下雨、超时、疲劳或缺票，方案应能说明下一步如何调整，并保护必要的交通、
用餐与恢复时间。

### 让攻略可以直接带走，让变化有路可走

最终交付采用**可直接复制的结构化文字**：行程概览、路线与时间安排、餐饮和住宿、
天气与准备、费用，以及待确认事项。核心项目、可删项目和相关条件写在对应环节，
旅行者可以保存到备忘录，按顺序使用。

关键环节提供具体的 **Plan B**：**何时切换 → 换到哪里 → 怎么过去 → 净增多少费用 →
几点接回原路线 → 删掉什么**。餐厅排队时，备选应落实到经过查询的另一家餐厅，
并考虑营业时段、路程、吃饭时间与后续预约；天气、停车、缺票或体力变化也采用
适用的替代或退出安排。查不到的替代会明确标注，保留实际可执行的退出选择。

每条重要备选分别检查时间与预算，替换支出按净差额计算，保留不可退费用与应急金。
多种突发情况同时发生时需要重新核算，避免把几个单独可行的备选直接叠加。

### 用全程成本选择住宿

住宿同时比较**房费、早餐、停车、接驳、次日出发位置和退改条件**。
当日往返则先判断是否需要住宿，避免为填满攻略而增加一晚开销。

仓库内的一组**虚构测试案例**展示了这种取舍：

| 两名成人、两日一晚 | 湖边住宿 | 旧城住宿 |
|---|---:|---:|
| 一间房一晚 | 360元 | 280元 |
| 两人早餐额外支出 | 0元 | 50元 |
| 全程当地交通 | 140元 | 190元 |
| 其他相同支出 | 230元 | 230元 |
| **基础支出合计** | **730元** | **750元** |

在这组条件下，湖边住宿全程便宜20元，并节省75分钟交通时间。
把住宿与路线一起算，才能看见旅行者实际付出的成本。
[查看测试证据与原始输出](evaluation/module-report.md)。

### 让天气真正影响安排

核对**预报发布时间、覆盖日期和适用地点**，再把降雨、风力、温度、能见度等信息
转成活动顺序、户外窗口、备选方案和复查节点。
远期出行区分季节背景与尚不可得的当日预报；雪山、云海、洞口光影等摄影目标
保留实际天气与观赏条件的不确定性。

### 用独立约束和脚本复查计划

附带的 Python 检查器会复查时段重叠、活动时长、开放窗口、截止时间、费用数量、
预算与应急额度。它支持**独立约束文件**：先记录旅行者要求与来源限制，再审计
生成的计划，检查草稿是否通过改写预算或截止时间偏离了原始需求。

JSON 是 agent 内部的检查材料，旅行者直接阅读普通语言的行程。

### 让信息缺口保持可见，同时继续规划

关键事实保留来源、适用日期、查询时点，以及 **已核实／估算／未知** 状态。
房态快照、地图估计和预算额度会分别说明含义。

某段路线、酒店价格或未来天气暂时查不到时，继续完成其他有依据的部分，
把缺口限定在受影响的位置。目标受限时继续寻找匹配偏好的候选方案，说明体验上的妥协。

## 一份计划会交付什么

| 内容 | 交付重点 |
|---|---|
| 推荐与取舍 | 为什么选这条路线，保留什么、删掉什么 |
| 路线与排程 | 有依据的点位顺序、门到门交通、用餐休息、返回与退出条件 |
| 住宿 | 是否需要过夜；需要时比较区域、具体候选与全程成本 |
| 天气 | 适用出行日期的信息、对活动的影响，以及必要的复查节点 |
| 预算 | 统一币种与全队口径，说明已付费用、可选增量、应急金和估算项 |
| Plan B | 可观察的触发条件、具体替代、切换交通、时间费用变化与回接位置 |
| 核验结果 | 已查证内容、剩余缺口、备选方案与审计范围 |

交付篇幅随旅行规模调整。短途一日游可以是一份简洁方案，多日行程再展开到每天。

## 安装与使用

```shell
git clone https://github.com/yilianghe/realistic-travel-planner-skill.git
cd realistic-travel-planner-skill
```

仓库内 `realistic-travel-planner/` 是可独立安装的 skill 文件夹；根目录的
测试、评估和 CI 用于维护与复查，不必放进技能目录。

Codex 用户把该文件夹放到自己的 `$CODEX_HOME/skills/`，未自定义时通常是
`~/.codex/skills/`。以 Windows PowerShell 为例，在仓库根目录执行：

```powershell
Copy-Item -LiteralPath .\realistic-travel-planner -Destination "$env:USERPROFILE\.codex\skills\realistic-travel-planner" -Recurse
```

目标文件夹若已存在，先比较本地改动，避免重复嵌套或覆盖自定义版本。
安装后在新会话中调用：

> 使用 $realistic-travel-planner，结合我已经提供的日期、作息、体力与预算规划旅行。
> 只补问会改变方案的信息，以可直接复制的结构化文字给出路线、住宿判断、天气、完整费用和删减条件。
> 为关键环节提供 Plan B，写明何时切换、具体替代、交通、时间与费用变化，以及如何接回后续行程。
> 对查不到的部分单独标注，继续完成其余有依据的规划。

其他支持 `SKILL.md` 的 agent 可按各自的技能目录规则安装。

## 检查器与验证

Python 3.10+，只用标准库，不联网、不操作账户：

```shell
python -m unittest discover -s tests -v
python scripts/validate_package.py
python realistic-travel-planner/scripts/audit_plan.py evaluation/audit-example.json --constraints evaluation/audit-constraints.json
```

检查重叠、时长下限、开放/入场窗口、截止时间、费用数量、预算与应急金，
以及事先声明的必需项目/费用类别。独立约束文件用于避免通过修改草稿中的
预算和截止时间把错误“检查通过”。[JSON 契约](realistic-travel-planner/references/audit-schema.md)
适用于中间审计文件，不要求旅行者阅读或手工编写 JSON。

检查器只验证输入数据；不能证明路线/费用已完整列出、信息真实、预约有票、
体力合适或旅行体验优秀。跨时区、夏令时和跨午夜行程需按契约另外处理。

## 测试与评估

见 [测试题](evaluation/cases.md)、[预先定义的观察标准](evaluation/rubric.md)、
[评估报告](evaluation/report.md) 和 [原始输出](evaluation/results/)。
测试覆盖需求确认、门到门排程、预算漏项、赶车时限，以及目标受限后的行程调整。
评估保留固定证据、观察标准与原始输出，便于复查规划依据。

另有一次 [真实官网访问检查](evaluation/live-check.md)，如实记录了网页读取失败；
不把搜索摘要当成完成核验。现有行为评估采用小样本、单次运行和作者判读，
结论仍需更多真实场景与实际出游反馈验证。

补充的路线、住宿、天气行为回归见 [模块测试](evaluation/module-cases.md) 与
[模块评估](evaluation/module-report.md)。第一版报告保留为历史记录，
后续模块的验证范围在对应报告中单独说明。所有公开新增案例均为虚构数据。

## 能力边界

本 skill 提供规划规则、交付要求和审计工具。实时地图、天气、酒店与票务数据
需要宿主具备可用的搜索、浏览器或相关服务；安装 skill 本身不会开通这些接口。
规划过程不包含预订、付款或自动监控。真实数据获取、实际出游体验和多次运行
的稳定性仍需要进一步验证。
